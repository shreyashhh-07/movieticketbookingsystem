# Movie Ticket Booking System

A Spring Boot REST API where users register, browse movies and book tickets, and admins manage the movie catalogue.

## 1. Project Overview

The system exposes a secured REST API (JSON over HTTP) built with Spring Boot, Spring Data JPA and MySQL.
Authentication uses **JWT tokens** and authorization uses two roles: `ROLE_USER` and `ROLE_ADMIN`.

## 2. Problem Statement

Booking cinema tickets manually (at the counter or by phone) is slow, error-prone and gives no live information about seat availability.
This project provides a backend that lets customers book tickets online while the system keeps seat counts and prices correct, and lets the cinema staff manage movies and monitor bookings.

## 3. Objectives

- Build a complete layered Spring Boot application (Controller → Service → Repository → Database).
- Demonstrate CRUD, JPA entity relationships and MySQL integration.
- Protect the API with Spring Security (BCrypt passwords, JWT, role-based access).
- Validate all input and return clean, structured JSON errors.
- Calculate prices on the server so clients cannot tamper with amounts.

## 4. Features

**User**
- Register and log in (JWT token)
- Browse all movies, view movie details, search by title, filter by genre / language
- Book tickets (total amount is calculated by the server)
- View own bookings and a single booking
- Change the number of seats or cancel a booking
- View and update own profile

**Admin**
- Log in as admin (default account is created on first start)
- Add, view, update and delete movies
- View all users and all bookings

## 6. System Architecture

```
Client (Postman)
      │  HTTP + JSON
      ▼
JwtAuthenticationFilter  → checks the Bearer token, sets the logged-in user
      ▼
Controller   → receives request, @Valid validation, calls service, returns ResponseEntity
      ▼
Service      → business rules (price calculation, seat availability, ownership checks)
      ▼
Repository   → Spring Data JPA interfaces (SQL generated by Hibernate)
      ▼
MySQL database

GlobalExceptionHandler (@RestControllerAdvice) turns any exception into a JSON error.
```

## 8. Database Design

Tables: `users`, `roles`, `user_roles`, `movies`, `bookings`. Full details are in [DATABASE_DESIGN.md](DATABASE_DESIGN.md).

## 9. Entity Relationships

```
USER ──< BOOKING >── MOVIE        (User 1 : N Booking,  Movie 1 : N Booking)
USER >──< ROLE                    (many-to-many through user_roles)
```

- `Booking` has `@ManyToOne User user` and `@ManyToOne Movie movie` → foreign keys `user_id`, `movie_id`.
- `User` and `Movie` have `@OneToMany(mappedBy = ...) List<Booking> bookings` (the inverse side).
- `User` has `@ManyToMany Set<Role> roles` with `@JoinTable(name = "user_roles")`.
- Entities are never returned directly; DTOs are used, so there is no infinite JSON recursion and no password leak.

## 11. Authentication & Authorization

1. `POST /api/auth/register` stores the user with a **BCrypt-hashed** password and role `ROLE_USER`.
2. `POST /api/auth/login` checks email + password through Spring Security's `AuthenticationManager` and returns a signed **JWT**.
3. The client sends `Authorization: Bearer <token>` on later requests.
4. `JwtAuthenticationFilter` validates the token and loads the user's roles from the database.
5. `SecurityConfig` decides access per URL (`/api/admin/**` → `hasRole("ADMIN")`, movie writes → admin, everything else → authenticated).
6. Ownership rules (a user may only see/change their own bookings and profile) are enforced in the service layer.
7. No token / invalid token → **401**. Valid token but wrong role or not the owner → **403**.

Default admin (created automatically on first start): `admin@movie.com` / `Admin@123`
(change with the environment variables `ADMIN_EMAIL`, `ADMIN_PASSWORD`).

## 12. Validation & Exception Handling

- DTOs carry Jakarta annotations (`@NotBlank`, `@Email`, `@Size`, `@Positive`, `@Min`, `@Max`, `@DecimalMin`, `@Pattern`, ...) and controllers use `@Valid @RequestBody`.
- `GlobalExceptionHandler` (`@RestControllerAdvice`) maps exceptions to one JSON format:

```json
{
  "timestamp": "2026-10-04T12:30:45.123",
  "status": 404,
  "error": "Not Found",
  "message": "Movie with id 10 not found",
  "path": "/api/movies/10"
}
```

| Situation | Exception | Status |
|---|---|---|
| Missing record | `ResourceNotFoundException` | 404 |
| Business rule broken (not enough seats, already cancelled) | `BadRequestException` | 400 |
| Invalid body / malformed JSON | `MethodArgumentNotValidException`, `HttpMessageNotReadableException` | 400 (with `validationErrors` map) |
| Duplicate email, movie/user still referenced | `DuplicateResourceException`, `ResourceInUseException`, `DataIntegrityViolationException` | 409 |
| Wrong credentials / no token | `AuthenticationException` / `SecurityErrorHandler` | 401 |
| Not allowed | `AccessDeniedException` / `SecurityErrorHandler` | 403 |
| Anything unexpected | `Exception` | 500 |

## 13. How to Run the Project

Requirements: **JDK 21 or newer**, **MySQL 8** (running locally). Maven is optional because the Maven Wrapper is included.

```bash
# 1. start MySQL, then (first run only, see section 14) make sure the database is empty
# 2. run the tests (they use an in-memory H2 database, MySQL is not needed)
./mvnw test            # Windows: mvnw.cmd test

# 3. start the application
./mvnw spring-boot:run # Windows: mvnw.cmd spring-boot:run
```

The API is then available at `http://localhost:8080`.
If you have Maven installed you can use `mvn` instead of `./mvnw`.

Configuration is read from environment variables (defaults in `application.properties`):

| Variable | Default |
|---|---|
| `DB_URL` | `jdbc:mysql://localhost:3306/movieticketdb?createDatabaseIfNotExist=true&...` |
| `DB_USERNAME` | `root` |
| `DB_PASSWORD` | `root123` |
| `JWT_SECRET` | demo secret (at least 32 characters; change for real use) |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | `admin@movie.com` / `Admin@123` |

## 14. MySQL Setup

```sql
-- optional: the URL contains createDatabaseIfNotExist=true, so this is done automatically
CREATE DATABASE movieticketdb;
```

Set your MySQL password through `DB_PASSWORD` (or edit the default in `application.properties`).
Hibernate (`spring.jpa.hibernate.ddl-auto=update`) creates/updates all tables automatically.

> **Important:** the earlier incomplete version of this project already created `movieticketdb` tables with an older structure
> (for example `bookings.seats`). Run `DROP DATABASE movieticketdb;` once before the first start of this version so that the new tables are created cleanly.

On start-up `DataInitializer` inserts `ROLE_USER`, `ROLE_ADMIN`, the default admin account and three sample movies.

## 16. Example Requests/Responses

**Register** – `POST /api/auth/register`
```json
{ "name": "Rahul Sharma", "email": "rahul@example.com", "password": "secret123", "phone": "9876543210" }
```
→ `201 Created`
```json
{ "id": 2, "name": "Rahul Sharma", "email": "rahul@example.com", "phone": "9876543210",
  "roles": ["ROLE_USER"], "createdAt": "2026-10-04T12:30:45.123" }
```

**Book tickets** – `POST /api/bookings` with `Authorization: Bearer <token>`
```json
{ "movieId": 1, "numberOfSeats": 3 }
```
→ `201 Created`
```json
{ "id": 1, "userId": 2, "userName": "Rahul Sharma", "movieId": 1, "movieTitle": "Inception",
  "numberOfSeats": 3, "ticketPrice": 250.00, "totalAmount": 750.00,
  "status": "CONFIRMED", "bookingTime": "2026-10-04T12:35:10.456" }
```

**Validation error** – `POST /api/bookings` with `{ "movieId": 1, "numberOfSeats": 0 }` → `400 Bad Request`
```json
{ "timestamp": "...", "status": 400, "error": "Bad Request", "message": "Validation failed",
  "path": "/api/bookings",
  "validationErrors": { "numberOfSeats": "At least 1 seat must be booked" } }
```
